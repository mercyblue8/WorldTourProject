WorldTour 프로젝트 구조·디자인·코드 검토
정리일: 2026-10-10

1. 평가 범위와 한계

- 개발 중인 프로젝트이므로 완성도, 국가 수, 콘텐츠 양, 미구현 기능은 평가하지 않는다.
- 지금까지 구현된 설계와 코드의 품질, 현재 구조로 개발을 계속할 때 생길 문제를 평가한다.
- 직전 검토에서 HTML·CSS·JS와 주요 이미지 원본을 확인했다.
- 직전 검토 당시 기존 테스트 37개가 모두 통과했다. 이 문서 저장을 위해 테스트를 다시 실행한 것은 아니다.
- 브라우저의 로컬 파일 접근 정책으로 실제 화면을 열지 못했다. 움직임과 모바일 조작감은 검증하지 못했으며, 시각적 판단은 이미지 원본과 CSS에 근거한다.
- 파일 크기는 측정했지만 실제 네트워크 로딩 시간이나 브라우저 성능 지표는 측정하지 않았다.
- 아래 제안은 검토 의견이다. 구현 완료 항목이나 자동 변경 지시가 아니다.

2. 전체 판단

현재 구조는 소규모 정적 웹사이트로서는 합리적이다. 화면 연출에 비해 모바일 탐색과 성능 설계가 약하고, 일부 공통 모듈에는 일본 페이지 의존성이 남아 있다.
코드를 버리고 다시 만들거나 프레임워크로 전환할 필요는 없다. 국가별 페이지를 늘리기 전에 이동 방식, 자산 크기, 공통 모듈의 경계를 정리하는 편이 좋다.

평가 영역별 판단
- 코드 분리와 가독성: 대체로 양호
- 애니메이션 상태·취소 처리: 강점
- 공통 모듈의 독립성: 일부 개선 필요
- 디자인 일관성: 화면별 표현을 연결할 기준 필요
- 모바일 탐색 설계: 우선 재검토 필요
- 이미지·영상 성능: 개선 우선순위 높음
- 테스트: 로직 검증은 유용하지만 실제 브라우저 검증은 별개

3. 기본 코드 구조와 강점

HTML, 스타일, 동작, 설정 데이터를 나누고 main.js에서 조합하는 방식은 현재 프로젝트에 적합하다. 라이브러리 의존성이 작고 기능별 수정 위치도 비교적 명확하다.

잘 처리된 부분
- 연속 클릭에 따른 중복 이동 방지
- Escape를 통한 전환 취소
- 취소 이후 완료되는 이미지·영상 비동기 작업 처리
- 뒤로 가기로 복원되는 페이지 상태 처리
- destroy()를 통한 이벤트·타이머 정리

참고 파일: pages/landing/js/transition.js

window.WorldTour와 일반 defer 스크립트는 서버 없이 HTML을 직접 여는 목적에 맞는 선택이다. 국가가 늘어날 때는 스크립트 로딩 순서와 설정 계약을 일정하게 유지해야 한다.

4. 공통 모듈의 일본 페이지 의존성

관찰
- pages/continents/common/js/country-navigation.js는 공통 기능이지만 .tokyo-hero__image를 직접 찾는다.
- pages/continents/asia/index.html은 일본 전용 스타일과 일본 이미지를 전환 미리보기로 직접 참조한다.

영향
현재 구조에서 목적지 데이터만 다른 국가로 추가하면 전환 미리보기에 일본 이미지가 계속 나올 수 있다. 국가 수의 문제가 아니라 확장 지점이 충분히 분리되지 않은 문제다.

개선 방향
- 국가 진입 모듈은 이동·취소·애니메이션을 담당한다.
- 목적지 이미지와 텍스트는 국가 설정으로 전달한다.
- 최근 카드 호버 모듈처럼 국가별 선택자를 제거하는 방향을 유지한다.
- 모든 짧은 코드를 공통화하지 않는다. 여러 곳에서 같은 책임을 맡는 동작을 분리한다.

5. 이동 기능과 연출의 결합

관찰
- pages/landing/css/page.css에서 GO 버튼은 약 3.71초 뒤부터 나타난다.
- pages/landing/js/transition.js는 로딩 영상의 ended 이벤트가 발생해야 지도 이동을 시작한다.
- 영상 재생이 실패하면 재시도를 안내하며, 화면에서 영상을 건너뛰고 지도로 진입하는 경로는 제공하지 않는다.

영향
첫 방문의 분위기를 만들 수 있지만 반복 방문에서는 대기가 누적된다. 목적지 이동이 영상 재생 성공에 종속돼 있어 재생 실패가 탐색을 막을 수 있다.

개선 방향
- 영상과 전환 효과를 유지하되 기본 이동 경로를 보장한다.
- 연출을 건너뛸 수 있게 한다.
- 영상 재생 실패 시에도 목적지로 이동할 수 있게 한다.

6. 모바일 지도 탐색

관찰
세계지도와 아시아 지도는 가로형 이미지를 화면 안에 통째로 맞춘다. 세로형 휴대폰에서는 국가명과 클릭 영역도 함께 축소된다.

pages/continents/common/js/selection.js에서 작은 국가의 클릭 영역은 SVG 좌표 기준 반지름 5, 지름 10이다. 지도 폭이 1672에서 390 CSS px로 줄어들면 해당 영역의 지름은 계산상 약 2.3 CSS px다.

영향
실제 기기 검증 전이라도 손가락으로 선택하기 어려운 크기다. 반응형 CSS가 있다는 사실만으로 모바일 사용성을 보장할 수 없다.

개선 방향
- 지도의 시각적 정체성은 유지한다.
- 모바일에서는 국가 목록을 함께 제공하거나 확대 후 선택하는 방식을 검토한다.
- 실제 휴대폰에서 터치 선택과 국가명 가독성을 검증한다.

7. 디자인 일관성

관찰
- 세계지도: 입체 지형과 다채로운 대륙 색상
- 아시아 지도: 어두운 배경과 얇은 경계선
- 일본 페이지: 풍경 사진과 흰 배경의 사진 카드

페이지별 분위기 변화는 여행 사이트에 어울린다. 다만 제목 체계, 버튼 모양, 여백, 색상 사용 규칙이 약하면 서로 다른 사이트를 연결한 인상을 줄 수 있다. 이 판단은 실제 렌더링이 아닌 이미지와 스타일에 근거한다.

shared/css/tokens.css에는 검토 당시 색상 변수 네 개만 있었고, 다른 색상·모서리·전환 시간은 개별 파일에 흩어져 있었다.

개선 방향
- 글자 크기 단계, 기본 여백, 버튼, 카드 모서리, 애니메이션 속도를 공통 기준으로 정한다.
- 국가별 개성은 사진과 강조색으로 표현한다.
- 현재 규모에 불필요하게 복잡한 디자인 시스템을 도입하지 않는다.

8. 일본 첫 화면의 텍스트와 문서 구조

관찰
- JapanMainPage.png에는 'こんにちは', 'Japan | 日本'이 이미지 자체에 포함돼 있다.
- 사진은 object-fit: cover로 표시된다.
- pages/asia-countries/japan/index.html의 유일한 h1은 인트로가 끝나면 hidden 처리된다.

영향
- 사진과 글자를 독립적으로 배치하거나 크기를 조정할 수 없다.
- 모바일에서 사진이 잘리거나 확대될 때 글자도 함께 영향을 받는다.
- 번역이나 문구 수정에 이미지 편집이 필요하다.
- 이미지 대체 텍스트는 있지만 인트로 이후 문서에서 탐색할 수 있는 h1은 사라진다.

개선 방향
- 사진과 HTML 제목을 분리한다.
- 인트로용 장식 문구와 페이지의 의미상 제목을 분리한다.
- 인트로 종료 후에도 의미상 페이지 제목을 유지한다.

9. 이미지·영상 성능

검토 당시 파일 크기(대략적인 MiB)
- pages/landing/videos/background.mp4: 23.08
- pages/asia-countries/japan/assets/images/JapanMainPage.png: 9.98
- pages/asia-countries/japan/assets/images/shibuya-sky.jpg: 6.49
- 일본 카드 이미지 네 개 합계: 13.38

관찰과 영향
- 400px 폭 카드에 6.49MiB 이미지를 사용하는 것은 표시 크기에 비해 부담이 크다.
- loading="lazy"는 로딩 시점을 늦추지만 파일 크기 자체를 줄이지 않는다.
- 아시아 페이지는 목적지 선택 전부터 일본 미리보기 이미지를 참조하고 디코딩을 요청한다.
- 파일 크기의 합은 실제 초기 네트워크 전송량과 같지 않으며, 실제 로딩 시간은 별도 측정이 필요하다.

개선 방향
- 표시 크기에 맞는 이미지 파생본을 만든다.
- 화면 크기에 따라 적절한 파일을 선택하게 한다.
- 카드용 이미지와 확대 보기용 원본을 분리한다.
- 전환 미리보기의 로딩 시점을 조정한다.
- JavaScript 미세 최적화보다 큰 이미지·영상부터 점검한다.

10. 테스트와 문서 관리

강점
기존 테스트 37개는 취소, 중복 클릭, 페이지 복원, 지도 영역, 사진 이동 등 로직을 검사한다. 실패 상황을 검사하는 테스트도 있다.

한계
직접 만든 DOM 모형을 사용하는 테스트는 다음을 보장하지 않는다.
- 실제 CSS 적용과 애니메이션 충돌 여부
- 휴대폰의 터치 선택
- 키보드 포커스의 실제 이동
- 브라우저별 영상 재생
- 이미지 로딩과 화면 표시 성능

문서·코드 정리 대상
- README.md는 일본 화면을 예전의 사진 두 장 슬라이더로 설명한다.
- 현재 일본 페이지에서 연결하지 않는 gallery.js와 gallery.css가 남아 있다.
- pages/asia-countries/japan/css/page.css에는 현재 HTML에서 사용하지 않는 .city-section 스타일이 남아 있다.
- 삭제 여부는 별도 판단하되 현재 사용 중인 구조와 이전 구현을 구분한다.

11. 권장 작업 순서

1순위: 영상 재생 실패와 관계없이 목적지 이동을 보장한다.
2순위: 큰 이미지의 크기·포맷·로딩 정책을 정리한다.
3순위: 모바일 지도 선택 방식을 실제 기기에서 검증하고 개선한다.
4순위: 공통 국가 진입 모듈에서 일본 의존성을 제거한다.
5순위: 이미지 속 제목을 HTML로 분리하고 공통 스타일 기준을 정한다.
6순위: 실제 브라우저 검증과 문서 정리를 진행한다.

개발 원칙
후속 기능 작업마다 공통 모듈 분리 필요성을 먼저 판단한다. 여러 국가에서 공유하는 동작은 공통 모듈에, 국가별 콘텐츠와 설정은 각 국가에 둔다. 특정 페이지에서만 필요한 기능은 불필요하게 공통화하지 않는다.
